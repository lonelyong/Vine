## 1. 目标（为什么做，而不是"更抽象"）

### 1.1 要改变的判断

今天判断一个新能力该放哪，需要回答四个问题："它属于内容还是镜像？会不会产生 delta？要不要进 memo 的键？
它要不要参与版本三元组？"—— 这四个问题**本身**就是设计的味道：它们是"两个可变世界"的产物，不是领域问题。

重设计后，判断变成两个问题：**"这是内容事实还是派生值？"**、**"它跨层的话，值长什么样？"**。

### 1.2 目标（每条对应一个可测的"好"）

| # | 目标 | 怎么算达成 |
|---|---|---|
| O1 | 跨层只有不可变值，可变对象只活在内容侧 | 跨层类型里没有一个可变字段（门禁扫） |
| O2 | 发布 = 一次指针交换；版本/镜像/delta/memo 不再是概念 | 这些类型的名字从 SDK 消失 |
| O3 | 身份稳定且**死后可判定**；寿命由引用算出来 | 陈旧句柄答 gone 的用例；无 parking 路径 |
| O4 | 计划声明式，误用**不可表达** | 会话形状入口 = 0；"帧在飞时改形状"的拒绝路径不存在 |
| O5 | 派生是纯函数：可并行、可复现、可 dump、可 replay | 同输入逐项相等；replay 后端能过图像用例 |
| O6 | 稳态零分配、成本可预算 | 帧内分配计数为 0（arena 外） |
| O7 | 一改一处：新增能力只加值，不改核心模型 | 扩展清单里每条只碰一层 |

### 1.3 非目标（明确不做，避免范围膨胀）

- **不改作者层 API 的形态**：`Node` setter、`Scene` 装配、材质/几何构造大体照旧。
- **不做内容侧多线程写**：一个 Scene 一个写者（顺序交接允许，见 `C2`）。
- **不做 GPU-driven / bindless**：没有第二个后端、没有实测瓶颈（`G8`）。
- **不做本层的自动 barrier / render graph**：同步归后端（`G2`）。
- **不承诺 ABI 稳定**：这是内部重构，跨模块边界仍走头文件（`C11`）。
- **不改 vsg 后端内部**：只改它与本层的接口形状。

## 2. 功能要求（`R#`）

### 2.1 内容层（作者）

| # | 要求 | 判据 |
|---|---|---|
| R1 | `Node` 的身份在**构造时**存在，与是否在树里无关 | 构造后即可取到 `NodeId`，且与插入前后相同 |
| R2 | 一个原型可被**任意多个位置**引用（同一 Scene 内多次、跨 Scene、跨 Session） | 同一 `NodeId` 出现在两处，改原型两处同时变 |
| R3 | 原型的内部折叠**算一次**；实例放置成本 = N × 原型行数（v1 物化），不是 N 次 | 5000 行原型 × 10 实例：折叠计数 = 1，放置乘法 = 5 万次（`T4` 分开计）；B 方案（共享 local rows）另测 |
| R4 | 树里存**位置**（`Instance`），不存节点本体；换父/重排不改变任何身份；`Instance` 对原型有明确的存活责任 | 换父后 `InstanceId`、`NodeId`、行身份都不变；原型析构后仍有实例时不悬垂（`T22`） |
| R5 | 快照里的隐藏 = **不产生行**（结构），不是命令上的标志位；作者层保留 `Node::setVisible`，由发布把它编译成结构 | 隐藏子树不产生行；作者 API 不变（审计 X7） |
| R6 | 节点的四类事实（放置 / 子 / 状态贡献 / 载荷）是**值**，折叠是值运算 | 折叠函数无副作用，可对同一输入重复调用 |
| R7 | 原型包含**必须无环**，检测在插入时 | 自包含被拒绝，并报一条诊断 |
| R8 | **行预算**可观测：实例数 × 原型行数超阈值报诊断 | 超预算用例产生 1 条 episode 诊断 |

### 2.2 发布层

| # | 要求 | 判据 |
|---|---|---|
| R9 | 发布是**一次原子指针交换**；发布之后内容侧改任何东西都影响不到在飞的帧；旧帧读旧 revision | 在飞帧的命令逐项不变（已有见证）；改材质/几何/程序后旧帧仍用旧值（`T17`） |
| R10 | 发布成本 = O(变了的块 + 变了的素材值)；元数据表未变时共享，不整体拷贝 | 2000 行改 1 行：只触碰它所在的块；5000 原型 1 次编辑 ≤ 50 µs（`N19` / `K11`） |
| R11 | **批内不发布**；一次批 = 一次发布；批内 `publish` 不返回 null | `publishCount` 只 +1；`publish` 返回 `Result`（未发布是显式状态，`T31`） |
| R12 | 材质/几何/程序的改动**不需要**调用方通知：发布时按 `id → revision` 比对发现 | 改 `Material::setXxx` 后下一次发布生效，调用方零操作 |
| R13 | 快照可导出**文本摘要**（行数/素材数/预算/版本）用于诊断 | 一条命令打印，且可被测试断言 |

### 2.3 派生层

| # | 要求 | 判据 |
|---|---|---|
| R14 | `select(snapshot, view)` 是纯函数：同输入逐项相同 | 两次调用逐项相等（`expectSameDrawList`） |
| R15 | 一帧内的**视图无关折叠只做一次**；逐视图只付裁剪与排序 | 折叠计数 = 1（多 pass 用例） |
| R16 | 视图相关行（billboard / 屏幕空间）逐视图重算，但不影响视图无关行的结果 | 混合用例：两类行都正确 |
| R17 | 排序键是**全序值**并文档化；透明与不透明两段 | 相同输入的顺序稳定；跨机器一致 |
| R18 | 拾取/锚点/fit 等查询吃 `FrameResult.query`（snapshot + poses + view），不吃活相机/活场景 | 相机或关节移开后按下，答案属于用户看到的那一帧（`T19` / `T20`） |
| R19 | 拾取返回**位置身份**：`InstanceId` + `NodeId` + row（值），不返回对象指针 | 同一原型的两个实例可区分（`T18`）；结果类型里没有指针 |
| R20 | 若后端并行 record，合并结果**确定性**；核心不承诺纯 record | 并行与串行的命令序列逐项相等；`record_micros` 由后端报告（审计 A13） |

### 2.4 执行层

| # | 要求 | 判据 |
|---|---|---|
| R21 | 会话形状（pass 集合 / 目标 / 表面）是**声明**，按名字在帧边界差分；`Target` 带 `SurfaceId` | 增删 pass 不调用任何 add/remove，下一帧生效；多表面可寻址（`T29`） |
| R22 | GPU 资源存活 ⟺ 被 Session 已接受或在飞的 Snapshot 引用；宿主自持快照不钉住资源 | 枚举会话已知快照即可预测回收集（`T25`） |
| R23 | 管线缓存键是值；可**预热查询**（给定快照，答它需要什么），且预热是会话的一等入口 | 预热后再录制的帧里 `builds` 增量为 0；`prepare(snapshot, plan)` 存在（`T7` 扩展） |
| R24 | 帧内除 arena 外零分配 | 分配计数断言 |
| R25 | 能力（caps）分**必选/可选**，会话创建时协商；不满足必选项则拒绝创建并说明 | 能力不足用例给出明确诊断而非黑屏 |
| R26 | 关闭有显式相位（停止 → 排空 → 释放），任何相位都可重入安全 | 重复 `shutdown` 不崩、不泄漏 |

### 2.5 宿主与横切

| # | 要求 | 判据 |
|---|---|---|
| R27 | 一个设备 = 一个 Session，可驱动多个表面（多窗口）；不是两个 Session 共享设备 | 一个 Session 两个 Surface（`T29`）；任何实现需要第二条引擎线程就违反 `I6` |
| R28 | 诊断带**稳定 code** + 结构化字段（pass/node/instance/slot 等），不只靠消息文本 | 测试按 code 断言 |
| R29 | 单位（像素/点/归一化）与颜色空间是**类型/值**，不在注释里约定 | 传错单位编译失败 |
| R30 | 帧值可 replay：录下来能离线重放出**同一命令序列** | replay 后端与实时路径逐项相等 |
| R31 | 内容引用带 **revision**（`ContentRef{id,rev}` 或不可变值指针）；旧快照永远读旧版 | `T17` / `K7` |
| R32 | 拾取/诊断的身份是**位置**：`InstanceId` + `NodeId` + row | `T18` |
| R33 | 共享原型属于**一个写者域**；Scene 的 publish 能发现被引用原型的 revision 变化 | `T21` / `K8` |
| R34 | `Instance` 对原型有明确存活责任；不允许悬垂 `NodeId` 进入下一次发布 | `T22` |
| R35 | `PoseSet` 的语义是“实例 local 覆盖 + 子树传播”；pose 后可剔除、可拾取 | `T26–T28` / `K9` |
| R36 | 预热查询是会话的一等入口（`prepare`）；可选能力缺失要出现在报告里 | `T7` / `T10` |
| R37 | 一个设备一个 Session 多条 Surface；`Target` / `FrameRequest` 带 `SurfaceId` | `T29` / `K10` |
| R38 | 计划校验：重复名字、环、未知输入、超 `kMaxPasses` 都有稳定 code | `T30` |
| R39 | `publish` 在批内不返回 null；未发布是显式的 `Result` / 上一份快照 | `T31` |

## 4. 硬约束（`C#`，违反即设计错误）

| # | 约束 | 为什么不可协商 |
|---|---|---|
| C1 | **跨层的一切类型不可变**；可变对象只活在内容侧 | `I1`：一旦有例外，"哪条路径会读到别人的写"就不可枚举 |
| C2 | 一个 Scene 同时**只有一个写者**；写者交接必须有 happens-before | 内容侧没有锁；没有同步边的"顺序"是数据竞争 |
| C2b | 一个原型和所有引用它的 Scene 属于**同一个写者域**；跨线程共享可变原型不支持 | 原型没有 Scene 反向指针；否则 publish 读 vs 另一线程写就是数据竞争（审计 A3） |
| C3 | 只有**一条引擎线程**碰设备 | 后端（vsg）非线程安全；并行只在纯值上做 |
| C4 | 身份**只由注册表生成**，没有第二个入口 | 唯一性靠单一分配者；多入口 = 唯一性没法证明 |
| C5 | `generation` 回绕时**退休该槽**，不复用 | ABA 会复活已死的句柄 |
| C6 | 原型包含无环 | 折叠/派生否则不终止 |
| C7 | 计划按**稳定名字**差分，不按指针 | 指针每帧都可能变，差分就变成"每帧重建" |
| C8 | 跨层的值类型不得带虚函数/继承 | 值要能整体拷贝、比较、序列化 |
| C9 | 诊断走**单一路由**，带 episode | 两处日志 = 计数不完整 = 门禁不可信 |
| C10 | 不新增第三方依赖 | 仓库标准 |
| C11 | 迁移期 public API **只增不改** | 分三步落地的前提 |
| C12 | 每一步都必须能**独立判死** | 见总纲 `K1–K11`（含 audit 的 `K7–K11`） |

## 6. 与现状需求的映射

今天 `../design/graphics-threading.md` 有 `C1–C20`、`R1–R17`。重设计后的关系：

| 今天 | 去向 | 说明 |
|---|---|---|
| C5 描述只在形状编辑时构造 | **保留**（成为三件套的一部分） | `Geometry::description` 已符合 |
| C8 一帧一次 drain | **消失** | 没有 delta 通道 |
| C9 present 只在引擎线程 | **保留**（成为 `I6`） | |
| C10 引擎线程不同步等 UI | **保留** | |
| C11 并行度 0/1 与串行逐位相同 | **保留并扩展** | 分块记录的确定性合并 |
| C12 镜像侧入口断言引擎线程 | **消失**（镜像不存在） | 今天这条也没实现，见下 |
| C13 校验和不进 Release 稳态 | **保留** | |
| C14 一次仿真步是一个批量 delta | **改写** | 批次仍存在，但不产生 delta：一次发布 |
| C15 脏集合合并 | **保留** | 变成脏块集合 |
| C16 两个半段各归一条线程 | **改写** | 变成"内容半段产出值、引擎半段消费值" |
| C17 表面事件只在帧首 | **保留** | |
| C18 批内版本不推进 | **改写** | 批 = 一次发布（`R11`） |
| C19 材质以值过帧 | **推广** | 变成 `I1`：所有跨层事实 |
| C20 会话形状只在帧间改 | **升格** | 从"运行时拒绝"变成"不可表达"（`R21`） |
| R1–R17 | 按 §2 吸收 | 语义保住，载体换成值与句柄 |

**顺带修一处现状不一致**：今天的 `C12` 声称"镜像侧入口断言引擎线程"，但代码里没有实现
（`src/viz/graphics/` 里除 `FrameRunner` 自身外没有线程断言）。重设计里这条约束消失，因此不必补断言；
若不采纳本提案，则应把 `C12` 改成事实（约定，不设断言）。
