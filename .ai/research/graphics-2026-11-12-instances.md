# graphics-2026-11-12：原型与实例（A6）——`T23` 的 A/B 测量口径

> **状态**：未采纳（研究 / 实验提案）
> **日期**：2026-11-12
> **范围**：快照 / 派生的 CPU 侧原型实例化；不含 GPU instancing、剔除 / 拾取算法与 pose。
> **相关**：`../design/graphics-frame-pipeline.md` §3.10 F10、§5.2 `R3`、§8 `T4` / `T23`、§8.1 `K11`、
> §9.3 步 6；`../research/graphics-2026-11-11-next-audit.md` A5；`../research/graphics-2026-11-11-next-design.md` `Q8`。

## 0. 一句话

`T23` 不是新判死阈值，是一张 A/B 对照表：先证明 A（物化）正确，再用同一夹具测 B（共享 local rows +
per-instance root transform）是否把快照行数与放置乘法降到 O(R + N)；数字不成立就停在“原型 DAG 共享”。

## 1. 背景

- `R3` 声明：原型内部折叠算一次；v1 的放置成本是 **N × 原型行数**，不是 N。
- audit A5：5000 行原型插 10 次，按物化写法是 50,000 次放置乘法，不是 10 次；内存按实例倍增。
- `Q8`：先 A 保证正确性；测 `T23` 的内存 / 放置成本后再决定 B。
- 今天 `T23` 只写了“5000 行 × 10 实例”，没有说明测什么、和谁比、什么算“数字好”。本文件把口径钉住。

## 2. 术语与夹具

- `R` = 原型行数 = 5000；`N` = 实例数 = 10；`S` = 一个实例内部被覆盖子树的 world 行数。
- A = 物化：`rows(instance) = Placement ∘ PrototypeLocalRows`，每个实例一份 world 行。
- B = 共享 local rows + per-instance root transform；有内部覆盖的实例把被覆盖子树物化。
- 夹具：1 个 5000 行原型（链式父子；行 = 快照 row，不是 Node 数），10 个实例，同一视图全部可见。
  同一夹具分别跑 A 与 B；A 先落地保证正确性，B 只在数字满足 §4 的判定线后成为默认。
- 编辑用例：
  - E0 稳态：连续 publish 两次、无编辑；第二次 `Unchanged`，`snapshot_rows` / 常驻不增。
  - E1 放置编辑：移动一个实例根。
  - E2 内部覆盖：改一个实例内部一个关节。
  - E3 原型编辑：改原型内部一个关节，10 个实例都应更新。

## 3. 测什么

每一项都给 A / B 并排；计数用测试内计数器（精确值，不靠时间反推），时间用 RelWithDebInfo 的中位数。

| # | 量 | A 的预期 | B 的预期 |
|---|---|---|---|
| M1 | `snapshot_rows` | `N × R` = 50,000 | `R + N` = 5,010；E2 再加 `S` |
| M2 | `draw_rows` | `N × R` = 50,000 | 同为 `N × R`；B 不减少，单独列出，不当作失败 |
| M3 | `placement_multiplications` | `N × R` = 50,000 | `R + N` = 5,010；E2 / E3 分开计 |
| M4 | `publish` / `select` 时间 | 实测中位数（A 的基线） | 实测中位数；B 不承诺下降，只要求不超 `K1` / `N2` / `K3` 预算 |
| M5 | 常驻字节 | 快照 row table + 元数据 | 同左；对“1× 原型快照”和“10 份独立拷贝”各取比值 |

补充：

- `N3`（快照常驻 ≤ 2× 行表字节数）照跑。注意它对 A 不构成区分：A 的行表本身就是 10×，`N3` 会轻松通过；
  必须另报 **对 1× 原型快照** 的比值，否则 A 钻空子。
- `K11`（5000 原型、1 次编辑的 publish）用原夹具照跑；它考的是元数据整体拷贝，不是实例化。
- draw list 是派生值；单独报它的字节与是否常驻，不算进 `N3`。
- 时间不重复设阈值：`K1`（2000 行改 1 行 publish ≤ 500 µs）、`N2`（≤ 250 µs）、`K3`（collect ≤ 2160 µs × 1.2）
  已经是现成的预算。

## 4. 判定线（不新增 `K#`）

A 只作正确性基线：先过 `T4` / `T21` / `T22`。

B 要成为默认，必须同时满足：

1. 静态实例 `snapshot_rows = O(R + N)`（E0 / E1 / E3 不随 R 增长）；
2. `placement_multiplications = R + N`（E1 的 publish 不随 R 增长）；
3. 常驻 ≤ 2× 1× 原型快照；
4. `K11` 的 5000 原型夹具仍绿。

任一不满足 ⇒ 停在“原型 DAG 共享”（§9.3 步 6 的回退线），不改 `K#`；把数字写回本文件或 ADR。

## 5. 不测 / 非目标

- GPU instancing、每实例 GPU 资源与 draw-call 合并；
- 剔除 / 拾取的按实例组合（它们由 `T18`–`T20` / `T24` 钉，不在 `T23` 里混算）；
- pose（`PoseSet`）的每帧更新成本；
- 多视图；`T23` 固定一个视图。

## 6. 怎么升级

- 数字满足 §4 ⇒ 写 ADR（A / B 的选择与代价），把结论写进 `design/graphics-frame-pipeline.md` §3.10 / §8.1；
  本文件可删除（git 是归档）。
- 数字不满足 ⇒ 保留“原型 DAG 共享”作为内容侧能力，不进入快照主路径；本文件记录实测后删除或留到引用被历史取代。

## 7. `G#`

- `G8`：没有真实宿主就不建实例化缓存；B 只由实测数字启用。
- `G10`：行数、乘法、常驻、publish / select 都要算，不只画。
- `G4`：`snapshot_rows` 与 `draw_rows` 分开说；B 不减少 draw 数。
